# control flow
    if
    else
    while
    for
    loop
    match

----------------------------------------
conditions
----------------------------------------

rules:
- conditions evaluate numeric zero-ness
- value 0 is false
- any non-zero value is true
- condition expressions do not require bool type
- condition expressions may use integer-compatible types

examples:
if(0)       // false
if(1)       // true
if(-1)      // true
if(ptr)     // true if non-zero

----------------------------------------
else
----------------------------------------

syntax:
else(condition){
    ...
}

fallback syntax:
else{
    ...
}

rules:
- else defines an alternative branch
- else may optionally contain a condition
- conditional else executes only if all previous branches failed
- unconditional else acts as fallback branch
- else chains evaluated top-to-bottom
- only one branch in chain may execute

supported by:
- if
- while
- match
- else

evaluation:
1. previous branch fails
2. evaluate else condition if present
3. execute branch if condition succeeds
4. otherwise continue chain

notes:
- else(condition) is primary language syntax
- else-if does not exist as separate syntax

----------------------------------------
if
----------------------------------------

syntax:
if(condition){
    ...
}

rules:
- condition evaluated once
- branch executes if condition succeeds
- may be followed by else branches
- branch scope isolated

evaluation:
1. evaluate condition
2. execute branch if non-zero
3. otherwise continue to else chain

----------------------------------------
while
----------------------------------------

syntax:
while(condition){
    ...
}

rules:
- condition checked before each iteration
- loop executes while condition succeeds
- may be followed by else branches
- else chain executes only if first condition check fails

evaluation:
1. evaluate condition
2. if zero:
    - continue to else chain
    - terminate loop
3. execute loop body
4. repeat from step 1

notes:
- break skips else chain

----------------------------------------
match
----------------------------------------

syntax:
match(value){
    (pattern){
        ...
    }
}else{
    ...
}

rules:
- match value evaluated once
- patterns checked top-to-bottom
- first matching pattern executes
- may be followed by else branches
- only one branch may execute
- duplicate patterns compile error

supported types:
- integer types
- trivial integer-compatible types

unsupported types:
- float
- string
- non-trivial objects

pattern forms:

single:
(1)

multi:
(2,3,4)

range:
(5 ~ 16)

range rules:
- inclusive lower bound
- inclusive upper bound
- range patterns require ordered comparable types

evaluation:
1. evaluate match value
2. compare against patterns in order
3. execute first matching branch
4. continue to else chain if no pattern matched

notes:
- only one match branch may execute (no fallthrough)
- ranges require ordered comparable types
- complex comparisons should use if/else chains

----------------------------------------
loop
----------------------------------------

infinite loop syntax:
loop{
    ...
}

counted loop syntax:
loop(N){
    ...
}

indexed counted loop syntax:
loop(N: i){
    ...
}

foreach loop syntax:
loop(array: item){
    ...
}

indexed foreach loop syntax:
loop(array: item : i){
    ...
}

rules:
- loop{} executes indefinitely
- loop(N) executes N iterations
- N is evaluated as expression
- N evaluated once before iteration begins
- loop(N: i) exposes current loop index
- counted loop index type always integer
- counted loop index increments by 1 automatically
- modifying loop index changes current iteration position
- loop(array: item) iterates sequentially over array elements
- loop(array: item : i) exposes both element and index
- foreach index type always integer
- loop-scoped variables local to loop body
- iteration source evaluated once before iteration begins

counted loop evaluation:
1. evaluate N expression
2. initialize index to 0
3. execute body
4. increment index by 1
5. repeat until index >= N

examples:
loop(10)
loop(count)
loop(get_count())
loop(base + offset)

foreach evaluation:
1. evaluate array expression
2. initialize index to 0
3. bind current element to item
4. execute body
5. increment index by 1
6. repeat until end reached

index modification behavior:
- incrementing index skips iterations
- decrementing index repeats iterations
- final automatic increment still occurs

examples:
i += 1    // skip next iteration
i -= 1    // repeat current iteration

notes:
- loop does not support else branches
- special iteration behavior should use for loops

----------------------------------------
logical and
----------------------------------------

syntax:
a && b

rules:
- evaluates left operand first
- if left operand is zero:
    - returns 0
    - right operand not evaluated
- otherwise evaluate right operand
- returns 1 if both operands non-zero
- otherwise returns 0

----------------------------------------
logical or
----------------------------------------

syntax:
a || b

rules:
- evaluates left operand first
- if left operand non-zero:
    - returns 1
    - right operand not evaluated
- otherwise evaluate right operand
- returns 1 if either operand non-zero
- otherwise returns 0

----------------------------------------
logical not
----------------------------------------

syntax:
!value

rules:
- evaluates operand truth value
- returns 1 if operand is zero
- returns 0 if operand is non-zero

----------------------------------------
bitwise and
----------------------------------------

syntax:
a & b

rules:
- performs bitwise and operation
- each output bit set only if corresponding bits set in both operands

----------------------------------------
bitwise or
----------------------------------------

syntax:
a | b

rules:
- performs bitwise or operation
- output bit set if corresponding bit set in either operand

----------------------------------------
bitwise xor
----------------------------------------

syntax:
a ^ b

rules:
- performs bitwise xor operation
- output bit set if corresponding operand bits differ

----------------------------------------
bitwise not
----------------------------------------

syntax:
~value

rules:
- inverts all bits in operand
- set bits become zero
- zero bits become set

----------------------------------------
left shift
----------------------------------------

syntax:
a << b

rules:
- shifts bits of left operand left by right operand count
- vacated bits filled with zero

----------------------------------------
right shift
----------------------------------------

syntax:
a >> b

rules:
- shifts bits of left operand right by right operand count

----------------------------------------
assignment
----------------------------------------

syntax:
a = b

rules:
- evaluates right operand
- stores result in left operand
- assignment is statement syntax
- assignment produces no value
- assignment cannot appear inside expressions

----------------------------------------
compound assignment
----------------------------------------

syntax:
a += b
a -= b
a *= b
a /= b
a %= b
a ^= b
a |= b
a &= b
a <<= b
a >>= b

rules:
- evaluates operation using current left operand value
- stores operation result into left operand
- compound assignment is statement syntax
- compound assignment produces no value

equivalent forms:
a += b     =>     a = a + b
a -= b     =>     a = a - b
a *= b     =>     a = a * b
a /= b     =>     a = a / b
a %= b     =>     a = a % b
a ^= b     =>     a = a ^ b
a |= b     =>     a = a | b
a &= b     =>     a = a & b
a <<= b    =>     a = a << b
a >>= b    =>     a = a >> b

----------------------------------------
type modifiers
----------------------------------------

rules:
- type modifiers modify type itself
- modifiers apply to all variables in declaration
- modifiers part of resulting type
- modifiers evaluated left-to-right

supported modifiers:
*
&
[N]

examples:
*int a,b,c;

equivalent meaning:
pointer to int a
pointer to int b
pointer to int c

&float x,y;

equivalent meaning:
reference to float x
reference to float y

int[4] values;

equivalent meaning:
array of 4 int values

----------------------------------------
pointer types
----------------------------------------

syntax:
*type value;

examples:
*int ptr;

rules:
- pointers store memory addresses
- pointers may contain zero value
- pointers nullable
- pointer references object of modified type

examples:
*int a,b;

equivalent meaning:
a -> pointer to int
b -> pointer to int

----------------------------------------

- indexing accesses offset memory location
- pointer indexing behaves as pointer offset dereference
- pointers remain distinct from arrays

----------------------------------------

- pointer arithmetic produces pointer result

----------------------------------------

----------------------------------------

----------------------------------------
static arrays
----------------------------------------

syntax:
type[N] value;

examples:
int[4] array;
int[4] v1,v2,v3;

array initialization syntax:
type[N] array = {value,value,value};

examples:
int[4] values = {1,2,3,4};

rules:
- static array is type modifier
- modifier applies to all declared variables
- N defines array element count
- N must be compile-time constant
- arrays occupy contiguous memory
- arrays indexed from 0
- compiler does not treat arrays as pointers
- array type includes element count

initialization rules:
- initializer values assigned sequentially by index
- initializer count must not exceed array size
- if initializer count smaller than array size:
    - final initializer value repeated for remaining elements

examples:
int[4] a,b;

equivalent meaning:
a -> array of 4 int values
b -> array of 4 int values

----------------------------------------
array indexing
----------------------------------------

syntax:
array[index]

rules:
- indexing accesses array element at index position
- first element index is 0
- last element index is len - 1

compile-time bounds checking:
- compiler validates constant index access
- invalid constant index access compile error

examples:
int[4] values;

values[0]    // valid
values[3]    // valid
values[4]    // invalid

----------------------------------------
array length
----------------------------------------

syntax:
array.len

rules:
- static arrays contain built-in len member
- len represents array element count
- len replaced at compile time with declared array size

examples:
int[8] values;

values.len    ->    8

----------------------------------------
array and pointer distinction
----------------------------------------

rules:
- arrays are not pointers
- arrays do not decay into pointers
- array types and pointer types are distinct
- compiler treats arrays and pointers differently

struct members

----------------------------------------
struct behavior
----------------------------------------

rules:
- structs are raw data containers
- structs do not contain member functions
- structs do not support private members
- constructors and destructors not part of struct data
- constructor and destructor implementations shared between all struct instances

----------------------------------------
struct constructors
----------------------------------------

syntax:
constructor(){}
constructor(type value,...){}

rules:
- structs may define multiple constructors
- constructors may accept parameters
- constructor called during struct creation
- constructor initializes struct instance
- constructor operates on current struct instance
- constructor executes after default member initialization
- constructor may overwrite default member values

----------------------------------------
struct destructors
----------------------------------------

syntax:
destructor(){}

rules:
- structs may define destructor
- destructor called before struct destruction
- destructor operates on current struct instance
- only one destructor allowed per struct

----------------------------------------
default struct member values
----------------------------------------

syntax:

examples:

rules:
- members may define default values
- default values applied during construction

----------------------------------------
struct transfers
----------------------------------------

syntax:
transfer(&type other){}

examples:
transfer(&name other){}

rules:
- structs may define one transfer function
- transfer defines struct assignment behavior
- transfer called during struct assignment
- transfer operates on source struct instance
- transfer receives destination instance reference
- transfer implementation fully controlled by struct author
- transfer may implement move behavior
- transfer may implement copy behavior
- transfer may implement deep copy behavior
- transfer replaces raw copy behavior completely

assignment evaluation:
a = b;

equivalent behavior:
b.transfer(a)

notes:
- transfer not part of struct data
- transfer implementation shared between all struct instances

----------------------------------------
self transfer
----------------------------------------

rules:
- transfer may receive same source and destination instance
- self transfer detection performed by comparing instance addresses

example:
&self == &other

----------------------------------------
default transfer behavior
----------------------------------------

rules:
- structs without transfer use raw memory copy
- structs with transfer always use transfer behavior
- raw copy never occurs when transfer defined

----------------------------------------
struct copy initialization
----------------------------------------

syntax:
type a = b;

rules:
- destination instance constructed first
- default constructor executed before transfer
- transfer executed after construction

evaluation:
1. create destination instance
2. execute default constructor
3. execute transfer

function declarations

func name[returns](parameters){

----------------------------------------
function return types
----------------------------------------

syntax:
[type,...]

rules:
- square brackets define return types
- functions may return zero or more values
- return type order preserved
- empty return list defines no-return function

examples:
[]                 // no returns
[int]              // single return
[int,int]          // two returns
[int,float,bool]   // three returns

----------------------------------------
function parameters
----------------------------------------

syntax:
(type name,...)

rules:
- function parameters declared inside parentheses
- parameters evaluated before function execution
- parameter order preserved

examples:
(int value)
(int a,int b,float c)

----------------------------------------
function returns
----------------------------------------

syntax:
ret expression,...;

rules:
- ret exits current function
- return values separated by commas
- returned expression count must match function return count
- return expressions evaluated left-to-right

examples:
ret 1;
ret a,b;
ret value + 1,other * 2;

----------------------------------------
function call behavior
----------------------------------------

rules:
- functions with zero returns cannot be used in expressions
- functions with single return behave as expression value
- functions with multiple returns require structural assignment
- return count mismatch compile error

----------------------------------------
single return assignment
----------------------------------------

examples:
a = fn();
int value = fn();

rules:
- single return functions may be assigned directly
- single return functions may be used inside expressions

----------------------------------------
multi return assignment
----------------------------------------

syntax:
a,b = func();

rules:
- assignment target count must match function return count
- assignment order preserved
- return values assigned left-to-right
- multi-return functions cannot be used as expression values

valid:
a,b = func();
int a,b = func();
_,b = func();

invalid:
a = func();
a,b,c = func();

----------------------------------------
return discard
----------------------------------------

syntax:
_

rules:
- underscore discards assigned return value
- discard does not create variable
- discard valid only in assignment position

examples:
_,b = func();
_,_,c = func();

----------------------------------------
return forwarding
----------------------------------------

rules:
- function identifiers inside ret expand to returned values
- forwarded return count must match current function return count

examples:
func fn1[int](){
    ret 1;
}
func fn2[int,int](){
    ret 1,2;
}
func fn3[int,int](){
    ret fn2;
}

invalid:
func fn4[int,int](){
    ret fn1;
}

# operation overloading

----------------------------------------
operation declarations
----------------------------------------

syntax:
operation symbol[returns](left)(right){
    code
}

examples:
operation +[vec](vec a)(vec b){
    ret vec(a.x + b.x,a.y + b.y);
}

----------------------------------------
operation return types
----------------------------------------

rules:
- operation return syntax identical to function return syntax
- operations may return zero or more values
- return count validated identically to functions

----------------------------------------
operation operands
----------------------------------------

syntax:
(left)(right)

rules:
- first parameter group defines left operand
- second parameter group defines right operand
- left operand receives left-side value
- right operand receives right-side value

example:
a + b

equivalent operand mapping:
left  -> a
right -> b

----------------------------------------
operation symbols
----------------------------------------

rules:
- operation name defines overloaded symbol
- symbol determines operation usage syntax

examples:
operation +
operation -
operation *
operation /

----------------------------------------
primitive operation restrictions
----------------------------------------

rules:
- primitive types cannot overload operations
- built-in primitive behavior always preserved

restricted types:
bool,int,uint,float,void
i8,i16,i32,i64
u8,u16,u32,u64
f32,f64

invalid:
operation /[int](int a)(int b){}

----------------------------------------
operation behavior
----------------------------------------

rules:
- overloaded operations selected using operand types
- operation operands evaluated before overload execution
- operation result used as expression result

----------------------------------------
supported operation overloads
----------------------------------------

overloadable binary operations:
+ - * / % 
== != < > <= >=
& | ^ << >>
[]

rules:
- only listed operations may be overloaded

----------------------------------------
non-overloadable operations
----------------------------------------

invalid operations:
&& ||
. ::
=
+= -= *= /= %=
&= |= ^= <<= >>=

----------------------------------------
non-overloadable unary operations
----------------------------------------

invalid unary operations:
&
*

----------------------------------------
bool operation restrictions
----------------------------------------

restricted operations:
== != < > <= >=

rules:
- bool types only support comparison operations
- arithmetic operations invalid for bool
- bitwise operations invalid for bool

----------------------------------------
operation resolution
----------------------------------------

rules:
- overload selected using operand types
- exact overload match required
- primitive operations always use built-in behavior
- overload resolution occurs at compile time

----------------------------------------
unary operation overloading
----------------------------------------

syntax:
operation symbol[returns](operand){
    code
}

examples:
operation -[vec](vec value){
    ret vec(-value.x,-value.y);
}
operation ![vec](vec value){
    ret vec(!value.x,!value.y);
}

----------------------------------------
unary operation rules
----------------------------------------

rules:
- unary operations use single operand group
- operand receives operation value
- unary operation result used as expression result
- unary overload selected using operand type

----------------------------------------
supported unary overloads
----------------------------------------

overloadable unary operations:
+ - ! ~

rules:
- unary overload syntax differs from binary overload syntax
- unary operations do not define right operand
