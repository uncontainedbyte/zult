# control flow
    if
    else
    while
    for
    loop
    match

----------------------------------------
conditions
----------------------------------------

rules:
- conditions evaluate numeric zero-ness
- value 0 is false
- any non-zero value is true
- condition expressions do not require bool type
- condition expressions may use integer-compatible types

examples:
if(0)       // false
if(1)       // true
if(-1)      // true
if(ptr)     // true if non-zero

----------------------------------------
else
----------------------------------------

syntax:
else(condition){
    ...
}

fallback syntax:
else{
    ...
}

rules:
- else defines an alternative branch
- else may optionally contain a condition
- conditional else executes only if all previous branches failed
- unconditional else acts as fallback branch
- else chains evaluated top-to-bottom
- only one branch in chain may execute

supported by:
- if
- while
- match
- else

evaluation:
1. previous branch fails
2. evaluate else condition if present
3. execute branch if condition succeeds
4. otherwise continue chain

notes:
- else(condition) is primary language syntax
- else-if does not exist as separate syntax

----------------------------------------
if
----------------------------------------

syntax:
if(condition){
    ...
}

rules:
- condition evaluated once
- branch executes if condition succeeds
- may be followed by else branches
- branch scope isolated

evaluation:
1. evaluate condition
2. execute branch if non-zero
3. otherwise continue to else chain

----------------------------------------
while
----------------------------------------

syntax:
while(condition){
    ...
}

rules:
- condition checked before each iteration
- loop executes while condition succeeds
- may be followed by else branches
- else chain executes only if first condition check fails

evaluation:
1. evaluate condition
2. if zero:
    - continue to else chain
    - terminate loop
3. execute loop body
4. repeat from step 1

notes:
- break skips else chain

----------------------------------------
match
----------------------------------------

syntax:
match(value){
    (pattern){
        ...
    }
}else{
    ...
}

rules:
- match value evaluated once
- patterns checked top-to-bottom
- first matching pattern executes
- may be followed by else branches
- only one branch may execute
- duplicate patterns compile error

supported types:
- integer types
- trivial integer-compatible types

unsupported types:
- float
- string
- non-trivial objects

pattern forms:

single:
(1)

multi:
(2,3,4)

range:
(5 ~ 16)

range rules:
- inclusive lower bound
- inclusive upper bound
- range patterns require ordered comparable types

evaluation:
1. evaluate match value
2. compare against patterns in order
3. execute first matching branch
4. continue to else chain if no pattern matched

notes:
- only one match branch may execute (no fallthrough)
- ranges require ordered comparable types
- complex comparisons should use if/else chains

----------------------------------------
loop
----------------------------------------

infinite loop syntax:
loop{
    ...
}

counted loop syntax:
loop(N){
    ...
}

indexed counted loop syntax:
loop(N: i){
    ...
}

foreach loop syntax:
loop(array: item){
    ...
}

indexed foreach loop syntax:
loop(array: item : i){
    ...
}

rules:
- loop{} executes indefinitely
- loop(N) executes N iterations
- N is evaluated as expression
- N evaluated once before iteration begins
- loop(N: i) exposes current loop index
- counted loop index type always integer
- counted loop index increments by 1 automatically
- modifying loop index changes current iteration position
- loop(array: item) iterates sequentially over array elements
- loop(array: item : i) exposes both element and index
- foreach index type always integer
- loop-scoped variables local to loop body
- iteration source evaluated once before iteration begins

counted loop evaluation:
1. evaluate N expression
2. initialize index to 0
3. execute body
4. increment index by 1
5. repeat until index >= N

examples:
loop(10)
loop(count)
loop(get_count())
loop(base + offset)

foreach evaluation:
1. evaluate array expression
2. initialize index to 0
3. bind current element to item
4. execute body
5. increment index by 1
6. repeat until end reached

index modification behavior:
- incrementing index skips iterations
- decrementing index repeats iterations
- final automatic increment still occurs

examples:
i += 1    // skip next iteration
i -= 1    // repeat current iteration

notes:
- loop does not support else branches
- special iteration behavior should use for loops

----------------------------------------

- returns 1 if both operands non-zero

- returns 1 if either operand non-zero
- otherwise returns 0

----------------------------------------
static arrays
----------------------------------------

syntax:
type[N] value;

examples:
int[4] array;
int[4] v1,v2,v3;

array initialization syntax:
type[N] array = {value,value,value};

examples:
int[4] values = {1,2,3,4};

rules:
- static array is type modifier
- modifier applies to all declared variables
- N defines array element count
- N must be compile-time constant
- arrays occupy contiguous memory
- arrays indexed from 0
- compiler does not treat arrays as pointers
- array type includes element count

initialization rules:
- initializer values assigned sequentially by index
- initializer count must not exceed array size
- if initializer count smaller than array size:
    - final initializer value repeated for remaining elements

examples:
int[4] a,b;

equivalent meaning:
a -> array of 4 int values
b -> array of 4 int values

----------------------------------------
array indexing
----------------------------------------

syntax:

rules:
- indexing accesses array element at index position
- first element index is 0
- last element index is len - 1

compile-time bounds checking:
- compiler validates constant index access
- invalid constant index access compile error

examples:
int[4] values;

values[0]    // valid
values[3]    // valid
values[4]    // invalid

----------------------------------------
struct transfers
----------------------------------------

syntax:
transfer(&type other){}

examples:
transfer(&name other){}

rules:
- structs may define one transfer function
- transfer defines struct assignment behavior
- transfer called during struct assignment
- transfer operates on source struct instance

- transfer implementation fully controlled by struct author

- transfer may implement copy behavior

----------------------------------------

----------------------------------------

----------------------------------------
function returns
----------------------------------------

syntax:
ret expression,...;

rules:
- ret exits current function
- return values separated by commas
- returned expression count must match function return count
- return expressions evaluated left-to-right

examples:
ret 1;
ret a,b;
ret value + 1,other * 2;

----------------------------------------
function call behavior
----------------------------------------

rules:
- functions with zero returns cannot be used in expressions
- functions with single return behave as expression value
- functions with multiple returns require structural assignment
- return count mismatch compile error

----------------------------------------
single return assignment
----------------------------------------

examples:
a = fn();
int value = fn();

rules:
- single return functions may be assigned directly
- single return functions may be used inside expressions

----------------------------------------
multi return assignment
----------------------------------------

syntax:
a,b = func();

rules:
- assignment target count must match function return count
- assignment order preserved
- return values assigned left-to-right
- multi-return functions cannot be used as expression values

valid:
a,b = func();
int a,b = func();
_,b = func();

invalid:
a = func();
a,b,c = func();

----------------------------------------
return discard
----------------------------------------

syntax:
_

rules:
- underscore discards assigned return value
- discard does not create variable
- discard valid only in assignment position

examples:
_,b = func();
_,_,c = func();

----------------------------------------
return forwarding
----------------------------------------

rules:
- function identifiers inside ret expand to returned values
- forwarded return count must match current function return count

examples:
func fn1[int](){
    ret 1;
}
func fn2[int,int](){
    ret 1,2;
}
func fn3[int,int](){
    ret fn2;
}

invalid:
func fn4[int,int](){
    ret fn1;
}

Lexer Documentation:
	--TokenTypes(enum class):
		ERROR:    Unrecognized tokens.
		Ident:    Identifiers (variables, functions).
		Const:    Numeric constants (integers, floats).
		Type:     Built-in data types (`int`, `float`).
		Symbol:   Punctuation (`{`, `(`, `,`).
		Keyword:  Reserved words (`ret`, `if`, `while`).
		Operator: Arithmetic, comparison, assignment (`+`, `==`, `=`).
		String:   String literals (`"Hello"`, `'C'`).
		Nothing:  Placeholder.
	
	Token(struct) Represents a single lexed unit:
		type:   The token's category.
		value:  The token's text content.
		line:   Starting line number.
		column: Starting column number.
	
	Tokens(Map)
		A constant lookup table (`std::unordered_map<std::string,TokenType>`) mapping strings like keywords, operators, and symbols to their `TokenType`.
	
	StringTokens(Map)
		A map (`std::unordered_map<std::string,int>`) defining delimiters for string literals (e.g., `"`, `'`).
	
	Comment-Definitions(`CommentType` struct & `CommentTypes` vector):
		CommentType:  Defines comment patterns with `start`, `end` (empty for single-line), and `isMultiline` flag.
		CommentTypes: A `std::vector` holding `CommentType` objects to support different comment syntaxes (e.g., `/' ... '/`, `//`).
	
	Utility Functions:
		std::string TokenTypeToString(TokenType type): Converts a `TokenType` enum to its string name.
		std::vector<std::string> SortTokensByLength(...): Sorts token strings by length (descending) to ensure longest-match precedence during lexing.
		bool safe_stoi(...): Robustly converts a string to an integer, handling different bases (binary, hex) and error conditions.
	
	class Lexer: performs tokenization:
		Public Method<std::vector<Token> lex(std::string& str)> The primary function to tokenize an input string.
			Takes the source code `str` as input.
			Splits the input into lines, storing them for context.
			Iterates through the input, skipping whitespace and newlines.
			Dispatches to specialized private methods (`lexIdent`, `lexNumber`, `lexComment`, `lexString`) or directly matches predefined tokens (operators, keywords, etc.) using the length-sorted list.
			Generates an `ERROR` token for unmatched characters.
			Returns a `std::vector` of `Token` objects.
		
		Private Helper Methods:
			char inc():   Reads the current character and then advances the internal string index.
			PeekRet peek(int offset = 0) const:   Safely reads a character at an `offset` from the current position without advancing. Returns a struct indicating if a character exists and its value.
			Token lexIdent(uint& ln, uint& cn):   Extracts identifiers or recognizes them as keywords if they match entries in the `Tokens` map.
			Token lexNumber(uint& ln, uint& cn):  Parses numeric constants, handling decimal, binary (e.g., `10b1010`), hexadecimal (e.g., `0xAF`), and floating-point numbers.
			bool lexComment(uint& ln, uint& cn):  Detects and consumes single-line and multi-line comments based on `CommentTypes`. Returns `true` if a comment was consumed.
			bool lexString(uint& ln, uint& cn, std::vector<Token>& tokens):   Detects and extracts string literals enclosed by delimiters defined in `StringTokens`. Returns `true` if a string was consumed.



Parser Documentation:
	--NodeType(enum class) Defines the types of nodes in the AST:
		Type:   A data type.
		Ident:  An identifier.
		Number: A numeric literal.
		Const:  A constant declaration.
		Func:   A function.
		Var:    A variable declaration.
		Ret:    A return statement.
		Prog:   The root of the program's AST.
		ERROR:  A parsing error.
		UnaryOp:A unary operator expression.
		BinOp:  A binary operator expression.
		Expr:   A general expression.
	
	Node(struct) Represents a single node in the Abstract Syntax Tree:
		type:   The node's type (`NodeType`).
		value:   The node's value (e.g., identifier name, literal value, operator symbol).
		token:   The source token from which this node was primarily derived.
		children:   A list of pointers to child nodes.
		errorData:   A list of strings for error messages specific to this node.
		Constructor:   Initializes a `Node` with its type, optional value, and associated token.
		Destructor:   Deallocates memory for all child nodes.
		void addError(const std::string& message):   Adds an error message to `errorData`.
	
	RULE(enum class) Defines specific patterns of tokens that the parser looks for:
		ConstTypeIdentEQ: Matches "const Type Identifier =".
		IdentOpenCurl:    Matches "Identifier (".
	
	Element(struct) A helper for `RULE` definitions, specifying a token type or value to match:
		Type:   The `TokenType` to match (or `TokenType::Nothing` to check `Value`).
		Value:  The specific string content to match.
	
	Rules(std::unordered_map<RULE, std::vector<Element>>):
		A constant lookup table mapping `RULE` enums to their detailed token sequences.
	
	PrecedenceInfo(struct) Defines properties for an operator's precedence and associativity:
		unaryPrecedence:   Precedence when used as a unary prefix operator.
		binaryPrecedence:  Precedence when used as a binary infix operator.
		isLeftAssociative: True if the operator is left-associative.
		Static Helpers:    `Unary`, `Binary`, `Both` (for convenient creation).
	
	Precedence(static const std::unordered_map<std::string, PrecedenceInfo>):
		A constant lookup table mapping operator strings (e.g., "+", "==") to their `PrecedenceInfo`.
	
	std::string NodeTypeToString(NodeType type):
		Converts a `NodeType` enum to its string name.
	
	class Parser: parses tokens to build an AST:
		Public Method:
			Node* parse(std::vector<Token> _tokens): The primary function to parse an input token stream.
				Takes a `std::vector` of `Token` objects as input.
				Returns the root `Node` of the generated AST.
			
		Private Helper Methods**
			Node* Start():    Initiates the parsing of the entire program.
			Node* Variable(): Parses a variable declaration.
			Node* Function(): Parses a function declaration or definition.
			Node* Block():    Parses a block of statements (e.g., `{ ... }`).
			Node* Arg():      Parses a function argument definition.
			Node* Return():   Parses a return statement.
			Node* Call():     Parses a function call.
			Node* Const():    Parses a constant declaration.
			Node* Struct():   Parses a struct definition.
			Node* Assign():   Parses an assignment statement.
			
			void pusherror(Node* node, Node* err, std::vector<std::string> errors):   Adds an `ERROR` node as a child, including specific error messages.
			void pushnext(Node* node, NodeType type):   Consumes the next token, creates a new node of the given type, and adds it as a child to `node`.
			void push(Node* node, Node* newnode):   Adds an existing `newnode` as a child to `node`.
			int fullcheck(std::vector<RULE> IDs):   Checks a list of `RULE`s in order and returns the 1-based index of the first match, without consuming tokens.
			PeekRet peek(int offset = 0) const:   Safely reads a token at an `offset` from the current position without advancing.
			Node* Expression(int minPrec):   Parses an expression based on operator precedence.
			TokenType Type(Token):   Returns the `TokenType` of a given `Token`.
			Node* ParsePrimary():   Parses basic expression components (literals, identifiers, parenthesized expressions).
			Node* ParseUnary():   Parses a unary expression or a primary expression.
			int check(RULE ID):   Checks if the current token sequence matches a `RULE` without consuming tokens.
			Token inc():   Consumes the current token and advances the parser's position.
