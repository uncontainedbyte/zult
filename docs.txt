Basic function declaration and returning.

Functions are declared using ‘func’ keyword followed by a name, returns, and arguments.

Example: func add[int](int A,int B);

[] are optional for no-return functions.
Functions can have 2 returns, a Value return, and an Error return.
An Error return must be a Primitive-type.
! marks a return as discardable.
`return` is used to return from functions.
double returns are NOT tuples.

Examples:

[]:none, [type]:single, [type:err]:double return.
[:err]: error only return.
[!type] [:!err] [!type:err] [type:!err] [!type:!err]: discardable.

Arguments are declare with a type, then name, and optionally a default value.
They are separated by comma`,`.

Code-Examples:

return;
return val;
return err; functions the same as ret val;
return val,err;
func name(){ block }
func name[](){ block }
func name[ret](){ block }
func add[int](int a,int b){
    return a+b;
}
func load[int:int](){ return data,err; }

Errors:
func fn[int:int](){ return 0; }
func fn[int](){ return 0,0; }





Basic if, else, and switch statements.

if:

condition evaluated once.
branch runs if condition not-zero(!0).
can be followed by else branches.

Examples:

if(condition){ block }
if(condition){ block }else{ block }

switch:

only accepts interger type values, int, char, enum, etc.
switch value evaluated once.
patterns checked top-to-bottom.
first matching pattern executes.
can be followed by else branches.
only one branch may execute.
auto breaks at end of pattern block.
patterns separated by comma(,) are OR based.
if no pattern matches, else chain is run.
tailing comma is fine.
all patterns work as specified with both positive and negative numbers.

Patterns:

(N):     value(value is N).
(A~B):   range(value is A or B or inbetween).
(PA,PB): multi pattern(PatternA or PatternB)
(*):     wild card(works like default in C)

examples:

switch(val){
    (pattern){ block }
    (pattern,pattern){ block }
}else{ block }: else runs if no pattern matches

else:

else defines an alternative branch
else can optionally have a condition
conditional else runs only if all previous branches failed
unconditional else acts as fallback branch
else chains evaluated top-to-bottom
only one branch in chain may execute

examples:

else(condition){ block }
else{ block }
if(condition){ block }else{ block }
if(condition){ block }else(condition){ block }else{ block }
switch(val){}else{ block }
switch(val){}else(condition){ block }else{ block }





Loops

for loops declare variable once, check a condition at the start of a loop, and preforms an operation at the end of a loop.
Example: for(int i;i<10;i+=1){ code };

Structs:

Structs are raw container for data, declared with `struct` fallowed by a name.
Structs can have variable declarations with optinal default values.
Members can be accessed with `.` operator for both direct structs and pointer struct members.
The structs name is used to define constructors and the deconstructor.
Example: myStruct(args){} constructor.
Add ~ to the beginning of the struct name to define the deconstructor.
Example: ~myStruct(){} deconstructor.
a deconstructor can not take arguments.
Unlike deconstructor, constructors can take arguments, and there can be more then one.
Structs are bitwise copied by default using `=`.
Overloading the := operator will allow you to custom copy/transfer logic.
Note: overloading := disabless bitwise copy `=`.
a constructor with no arguments runs at declaration if no other constructor does.
A deconstructor runs at end of struct declarations scope.
If a deconstructor is defined, bitwise copy is disabled `=`.

Modifiers:

packed: makes struct have no padding.
align(N): makes struct allign to N bytes.

Examples:

struct myStruct{char,int}: 8 bytes or more.
packed struct myStruct{char,int}: 5 bytes.
align(16) struct myStruct{char,int}: 16 bytes.
struct vec2i{
    int x = 0,y = 0;
    vec2i(int xin,int yin){
        x = xin;
        y = yin;
    }
    ~vec2i(){ // functionally useless in this example.
        x=0;
        y=0;
    }
}





Member Functions

Member functions are declared with `func` fallowed by the type `.` and the functions name, its returns, and its inputs.
Example: func vec.normalize[vec](){ code }
Example: func float.round[float](){ code }
`self` is a pointer to the one calling the member function.
Example: 1.3.round(), self is a pointer to the float 1.3.
`self` can only be used withint the member function.
Member functions are not declared within anything, they are global.
Member functions work for structs, enums, and types.
Member functions can be members of namespaces.

Enums

An enum is declared with keyword `enum` fallowed by a type and name.
Example: enum int Err{Failed,Success}
An enum can have explicit values set by the user.
Enums do not need to be cast to be assigned to there type.
Example: int val = Err::Success;
However you need to cast to the enum to assign it a none enum value.
Example: Err val = (Err)0;
If an enum is declared without a type, it will default to `int`.
When used in switch statement, all values must be checked unless a wild card `*` or else statement is present.
Enums have a built in member function `name` which returns a string reprosenting the current value.
Example: Err::Success.name(); returns a pointer to a string that says “Success”.


Examples:

enum type name{
    name,
    name,
    ...
}
enum u8 Err{
    success,
    failed,
    unknown
}





Namespaces & Using

Namespaces are wrappers for global things like structs, enums, functions, variables, etc.
Namespaces are declared with keyword `namespace` fallowed by a name.
Example: namespace name{ code }
`private` is used to restrict something to only its namespace.
Namespaces can be nested.
Namespace members can be accessed with `::`.
Example: namespace::member;
Namespaces without a name are scoped to the file there in.

Using is used to make alises.
Example: using Byte = u8;
Example: using String = *char;
Example: using Math::PI;  imports Math::PI as just PI.
Example: using Render = Engine::Graphics::Renderer;

Type-Safe Structure-of-Arrays (SoA) Variadic System Specification
Component	Memory Location	Internal Representation	Runtime Cost
Metadata Array (types[])	.rodata (Static Memory)	Compiler-generated descriptor array	0 allocation cost; passed as a static 16-byte (ptr, len) slice
Data Array (payload[])	Caller Stack Frame	Contiguous array of uniform 64-bit (8-byte) slots	O(1) indexing; total size = N×8 bytes
Memory & Storage Layout Matrix
Argument Type	Storage Mechanism	Slot Payload	Semantics Preserved
Primitives (≤64-bit)	Direct Slot	Padded raw value	Pass-by-value
Floats (float, double)	Direct Slot	IEEE-754 bit representation	Pass-by-value
Pointers / Strings (char*)	Direct Slot	64-bit memory address	Pass-by-reference
Large Structs (>64-bit)	Spill to Stack Copy	Pointer to caller-allocated temp copy	Pass-by-value (mutation-safe)
Vector / SIMD (__m128)	Spill to Aligned Stack	Pointer to 16/32-byte aligned temp	Pass-by-value
Compilation & Execution Pipeline
    1. Static Analysis: Compiler evaluates variadic arguments at call site, matching inputs against static rules.
    2. Descriptor Generation: Compiler bakes type enum array into .rodata (e.g., [TYPE_INT32, TYPE_STR, TYPE_STRUCT]).
    3. Caller Frame Setup:
        ◦ Calculates required payload slots (N×8 bytes).
        ◦ Allocates isolated stack copies for any large structs or SIMD types to preserve value isolation.
    4. Stack Packing: Writes direct values and temporary pointers sequentially into contiguous 64-bit slots.
    5. Callee Execution:
        ◦ Callee reads payload[i] via simple O(1) array offset math: base_address + (i * 8).
        ◦ Evaluates types[i] at compile-time (if inlined) or via fast jump table (if opaque function).
    6. Zero-Cost Forwarding: Callee can forward both array slice headers (types and payload) down call chains without stack repacking.
Comparative Trade-off Analysis
    • vs. C (va_list): Eliminates memory corruption risks and manual format string tracking while maintaining low binary size and raw memory speed.
    • vs. C++ (Variadic Templates): Eliminates executable code bloat caused by generating unique function instances for every type combination.
    • vs. Go / Dynamic Languages (...any): Eliminates runtime heap allocations, GC tracking overhead, and interface boxing.
    • Primary Trade-off: Bypasses ABI CPU-register parameter passing (RDI, RSI) for variadic inputs in favor of stack packing to enable contiguous O(1) indexing.
